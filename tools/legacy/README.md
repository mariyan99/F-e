# Legacy export tool

Един скрипт, който изважда безопасния `/legacy` пакет от стария сайт вместо теб.

**Защо изобщо съществува:** аз работя в отдалечен контейнер в облака и нямам достъп до
`C:\Users\mariyan\...`. Не мога да чета твоя диск, каквото и разрешение да ми дадеш. Затова
екстракцията е автоматизирана — ти пускаш една команда, скриптът върши работата.

## Пускане

Отвори **Windows PowerShell** (не CMD), после:

```powershell
cd $HOME\Desktop
git clone https://github.com/mariyan99/F-e.git fabrizia-repo
cd fabrizia-repo
git checkout claude/fabrizia-ecommerce-rebuild-b9vo46

.\tools\legacy\Export-LegacyPackage.ps1 `
    -SourcePath "C:\Users\mariyan\OneDrive\Desktop\fabrizia\fabriziafashion-main" `
    -OutPath    "$HOME\Desktop\legacy-package"
```

Ако Windows откаже да пусне скрипта:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\legacy\Export-LegacyPackage.ps1 `
    -SourcePath "..." -OutPath "..."
```

Ако базата е само в `db.rar` — разархивирай я първо. Скриптът **нарочно** не разпакова архиви:
разпакетирането на дъмп с неизвестно съдържание е точно мястото, където изтичат лични данни.

## Какво прави

| Изход | Съдържание |
|---|---|
| `db/schema.sql` | структурата на базата, **без нито един INSERT** — по конструкция, не по филтър |
| `db/table_counts.txt` | име на таблица и приблизителен брой редове, само числа |
| `db/catalog_data.sql` | редове само от каталожни таблици, преминали PII проверка |
| `code/` | кодът без vendor, медия и архиви; стойностите на креденшъли заменени |
| `code-summaries/` | файловете, които **не** се копират — сметки, поръчки, админ, поща, плащания и всичко, което е тропнало по скенера. За всеки: какво прави, кои таблици ползва, кои хостове вика — без нито един ред от кода му |
| `branding/colors_used.txt` · `fonts_used.txt` | цветове и шрифтове, подредени по честота |
| `urls/` | локално намерените sitemap файлове |
| `images/images_inventory.tsv` | име, ширина, височина, съотношение, тегло — за всяко изображение |
| `images/aspect_ratios.txt` | разпределение на съотношенията: колко изобщо са близо до 3:4 |
| `images/samples/` | примерни снимки, разпределени из целия каталог, не първите N от една папка |
| `README.txt` | двата въпроса, на които трябва да отговориш |
| `EXPORT-REPORT.txt` | какво е изнесено, какво е задържано и защо |

## Как пази данните

Три независими бариери, не една:

1. **Deny списък** решава кои таблици изобщо имат право да изнесат редове. `user`, `customer`,
   `address`, `order`, `session`, `password`, `admin`, `log`, `newsletter` и подобни — никога.
   Deny винаги бие allow: таблица `product_customer_reviews` е лични данни първо и каталог второ.
2. **PII проверка** пре-сканира всеки ред, който е минал първата бариера. Имейл, български
   мобилен номер или IBAN → цялата таблица отпада.
3. **Чувствителният код се описва, не се възпроизвежда.** Файловете за сметки, поръчки, админ,
   поща и плащания не се копират. Вместо тях се пише резюме: класове, функции, ползвани таблици,
   външни хостове. Достатъчно за одита, безполезно за изтичане.
4. **Финално сканиране** минава през целия изходен пакет. Файл, който тропне, се заменя с резюме
   автоматично; ако въпреки това нещо оцелее, се създава `FLAGGED-DO-NOT-UPLOAD.txt` и скриптът
   излиза с код 2.

Трети party библиотеки — PHPMailer, minify, composer, jQuery и подобни — не се копират изобщо.
Те не казват нищо за магазина и бяха източникът на почти всички фалшиви тревоги при първия пуск.

Скриптът е **само за четене** върху източника: не пише, не мести и не трие нищо в стария сайт.
Нищо не се качва никъде — писва в папка по твой избор и спира.

## Изходни кодове

| Код | Значение |
|---|---|
| `0` | пакетът е чист и може да се качи |
| `2` | финалната проверка се провали — **не качвай** |

## Ако финалното сканиране се провали

Не качвай папката. Отвори `FLAGGED-DO-NOT-UPLOAD.txt`, виж кои файлове са маркирани, махни или
заличи проблемното, изтрий флаг файла и пусни скрипта отново в нова папка.

## Какво трябва да добавиш ръчно

Две неща, които никой скрипт не може да извади от диска:

- **Експорт от Google Search Console** — Ефективност → Страници → Експорт, последните 16 месеца.
  Това е най-важният източник за 301 картата.
- **Екранни снимки** в `screenshots\` — начална, категория, продукт, кошница, checkout, админ.
